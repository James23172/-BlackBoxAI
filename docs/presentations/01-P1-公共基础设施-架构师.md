## 开场白

各位老师好，我是本项目的架构师，负责整个系统的公共基础设施层——**common模块**。如果把我们的系统比作一栋大楼，我做的就是打地基的工作：Redis黑板存储、RabbitMQ消息通信、分布式锁、以及一键启动器。这些是所有模块运行的底层支撑，代码量约600行，涵盖6个核心类。

## 一、为什么选择"黑板+消息总线"架构？

传统的多机器人系统通常采用中心化控制——一个大脑告诉所有机器人每一步该做什么。但在我们的场景中，4辆小车需要在40×40的未知地图上独立决策、共享发现，集中式会导致单点瓶颈。

我们的方案是**C2风格的黑板架构**：

```
┌─────────────────────────────────────────┐
│                 Redis 黑板               │
│  map:blocked(位图)  map:view(位图)      │
│  car:{id}:pos/status/steps             │
│  unexplored:set(未探索索引)             │
│  taskQueue(任务队列)                    │
└────┬──────┬──────┬──────┬──────┬────────┘
     │      │      │      │      │
  Nav    Car   Target  Ctrl  Display
```

核心思想：**写黑板的人只管写，读黑板的人只管读，中间通过RabbitMQ做事件通知**。这实现了模块间的完全解耦——Navigator不需要知道Car的存在，Car不需要知道TargetPlanner的存在。

## 二、关键技术决策

### 1. 地图存储：Redis Bitmap 而非 JSON/数据库

这是本项目最重要的存储决策。40×40=1600个格子，每个格子2种状态（是否障碍、是否已探索），如果存JSON需要约50KB；我们用Bitmap，只需要1600bit = **200字节**，并且支持O(1)的BITCOUNT统计探索率、BITOP做集合运算。

```java
// 探索率计算 —— 一行命令搞定，无需遍历
jedis.bitcount("map:view");                    // 已探索格数
jedis.bitcount("map:blocked");                  // 障碍物格数
// 探索率 = bitcount(view) / (1600 - bitcount(blocked))
```

### 2. 位图版本号缓存机制

Navigator每次规划路径需要读完整地图。如果每次都从Redis解码1600bit，开销不小。我设计了一个**版本号缓存**：

```java
// BlackboardClient 核心逻辑
int currentVersion = parseVersionFromBitmap(jedis.get("map:view"));
if (currentVersion != cachedVersion) {
    cachedBitmap = decodeBitmap(jedis.get("map:view"));
    cachedVersion = currentVersion;
}
return cachedBitmap;
```

只有地图发生变化时（写入时递增版本号）才重新解码，减少了90%以上的冗余计算。

### 3. 分布式锁：SET NX EX + Lua原子释放

多辆小车可能同时抢占同一个目标。我实现了基于Redis的分布式锁：

```java
// 加锁
String ok = jedis.set(lockKey, lockValue, "NX", "EX", 30);
// 原子释放（Lua脚本保证 value 匹配才删，防止误删他人锁）
jedis.eval("if redis.call('get',KEYS[1])==ARGV[1] then return redis.call('del',KEYS[1]) else return 0 end", ...);
```

### 4. RabbitMQ Channel 线程安全封装

RabbitMQ的Channel不是线程安全的。我通过`synchronized`锁保护发送操作，并在连接断开时通过ShutdownListener自动重建Channel和队列绑定。

### 5. Launcher 一键启动器

开发阶段逐一启动9个模块太繁琐。我写了`Launcher.java`，自动执行`mvn compile`、检测端口占用并清理、然后并行fork所有子进程。团队成员只需跑一次`Launcher.main()`即可启动整个系统。

## 三、协作接口

我定义的公共接口被所有模块依赖：

| 接口 | 调用方 | 说明 |
|------|--------|------|
| `BlackboardClient` | 所有模块 | Redis读写唯一入口，封装Bitmap/Pipeline/版本号 |
| `MessageBusClient` | 所有模块 | RabbitMQ连接池，队列声明，Fanout发布 |
| `DistributedLock` | Car/TargetPlanner | 分布式锁，防多车抢占同一目标 |
| `ArgsParser` | 所有main() | 命令行参数解析，支持--redis-host等 |
| `CarState/Point/MQMessage/SimulationState` | 所有模块 | 共享数据模型 |
| `ConfigConstants` | 所有模块 | 集中管理默认端口/队列名/IP |

---

## 四、亮点总结

1. **Bitmap存储**：1600格地图仅200字节，探索率O(1)计算，Pipeline批量写入
2. **版本号缓存**：避免Navigator每次全量解码Bitmap，减少90%冗余计算
3. **零侵入基础设施**：任何模块只需new BlackboardClient()即可读写黑板，无需预先注册或配置
