## 二、WebSocket实时推送：两个关键设计

### 2.1 连接即认证

WebSocket连接建立后，第一件事必须是认证，而不是直接收发数据：

```java
// 客户端连接
客户端 → AUTH {"token":"eyJhbGc..."}
       ← AUTH_OK {"role":"OPERATOR","username":"user1"}
       ← 此后所有消息都按OPERATOR角色鉴权

// 如果token无效
客户端 → AUTH {"token":"invalid"}
       ← AUTH_FAIL {"reason":"Token过期，请重新登录"}
       → 连接被关闭
```

这样设计的好处：WebSocket上不会有任何匿名连接，每个指令都知道"是谁发的、能不能发"。

### 2.2 Fanout Exchange毫秒级同步

5台电脑的画面如何做到同步？答案在RabbitMQ的Fanout Exchange：

```
Controller 每200ms
  │
  └── fanoutPublish("REFRESH_ALL", allCarStates)
        │
        ├── Display(主公机:8888) → broadcast → 浏览器8888
        ├── Display(客户端B:8889) → broadcast → 浏览器8889
        ├── Display(客户端C:8890) → broadcast → 浏览器8890
        ├── Display(客户端D:8891) → broadcast → 浏览器8891
        └── Display(客户端E:8892) → broadcast → 浏览器8892

Fanout Exchange保证所有人收到完全相同的数据，误差<5ms
```

这也是为什么5台电脑的画面看起来完全同步——不是靠轮询，是靠RabbitMQ的扇出广播。

## 三、前端：三面板角色化渲染

前端是一个单文件HTML（约560行CSS+JS），根据登录角色显示三种完全不同的界面：

### 3.1 配置员面板
- 地图参数设置（宽/高/障碍物密度/小车数量）
- 障碍物编辑（随机生成 or 鼠标点击切换）
- 用户管理（创建/删除用户，权限表AES加密）
- 全局控制按钮（开始/暂停/重置，最高权限）

### 3.2 运行员面板
- 我的小车列表（位置、步数、状态）
- 暂停/恢复我的车（只控制自己的）
- 添加新车按钮
- **权限锁定提示**：配置员全局暂停时，所有按钮变灰，显示红色警告"配置员已全局暂停"

### 3.3 分析员面板
- 回放控制条（播放/暂停/加速/减速/逐帧前进后退/拖动进度条）
- 探索率折线图（X轴时间，Y轴探索率，Chart.js绘制）
- 单车统计表格（每辆车的步数、覆盖率贡献）

### 3.4 共享的画布渲染

无论哪个角色，左侧都是同样的Canvas地图画布：

```
Canvas 40×40格渲染逻辑：
  障碍物 ██ 深红色 → 从Redis map:blocked位图读取
  已探索 ░░ 浅蓝色 → 从Redis map:view位图读取  
  未探索 ·· 深灰色 → (1 - map:view位)的区域
  小车   ●  绿色圆 → 从car:{id}:pos读取坐标
  小车标签 Car001 → 绘制在圆上方
```

每帧渲染约1600个矩形，在Canvas上完成仅需2-3ms，完全不会卡顿。

## 四、ReplayServer：回放系统

回放功能是我的第二大模块，让分析员可以回溯任何时刻的地图状态。

### 4.1 批量快照API

```java
// POST /api/replay/snapshot/batch
// 请求: { "startTick": 0, "endTick": 1000, "step": 100 }
// 返回: [tick0的完整状态, tick100, tick200, ... tick1000]
```

Controller每个tick结束时，将`SimulationState`序列化后LPUSH到`replay:snapshots`列表。分析员通过API获取任意tick范围的批量快照。

### 4.2 三点回放设计

| 接口 | 端点 | 功能 |
|------|------|------|
| 快照列表 | GET /api/replay/snapshots?start=0&end=1000 | 获取tick范围 |
| 单帧快照 | GET /api/replay/snapshot?tick=500 | 获取某一帧的完整地图状态 |
| 指标数据 | GET /api/replay/metrics | 全局统计（总步数、耗时、探索率） |

### 4.3 前端回放面板

分析员面板的核心交互：

```
⏮ ──→ 跳到tick=0
⏪ ──→ 减速（1x→0.5x→0.25x）
⏸ ──→ 暂停回放
▶  ──→ 播放
⏩ ──→ 加速（1x→2x→4x→8x）
⏭ ──→ 跳到最新tick

[████████░░░░░░░░] 进度条 ← 拖动跳任意tick
```

当用户拖动进度条到tick=500时，前端向后端请求`/api/replay/snapshot?tick=500`，获取500时刻的完整地图状态，然后重新绘制Canvas。

## 六、亮点总结

1. **Fanout Exchange毫秒同步**：5台电脑画面<5ms误差，不是轮询，是扇出广播
2. **三级角色面板**：同一套代码、不同角色看到完全不同的界面，前端根据Token中的role字段动态渲染
3. **回放任意跳转**：支持拖动进度条跳到任何tick，后端批量快照API返回历史完整状态
4. **Canvas高效渲染**：40×40格1600个矩形，GPU加速Canvas，2-3ms完成一帧
